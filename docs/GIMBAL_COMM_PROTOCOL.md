# 云台、视觉与底盘通信协议 v1

本协议对应本仓库 `gimbal/App/gimbal_protocol.c` 和 `gimbal/App/gimbal_task.c` 的实际实现。
硬件映射为 USART10（PE2 RX / PE3 TX）接视觉、USART1（PA10 RX，板上丝印 USART1 的 3 针口）接底盘，UART7（带 VCC 的 4 针口）接蓝牙遥测（固件宏 `GIMBAL_VISION_UART`、`GIMBAL_CHASSIS_UART`、`TELEMETRY_UART`）。2026-10-21 起底盘由 UART7 改为 USART1：底盘线实际一直插在 USART1 口上，之前固件在 UART7 上收，底盘链路并未生效。后续接线变化时需同步修改固件和本文。

## 1. 接口和传输规则

| 接口 | 云台板引脚（当前工程配置） | 用途 |
|---|---|---|
| USART10 | PE2 RX、PE3 TX | 接收视觉目标误差 |
| USART1 | PA10 RX、PA9 TX | 接收底盘模式及 IMU 数据 |
| UART7 | PE7 RX、PE8 TX | 蓝牙遥测（VOFA+ JustFloat，见 `gimbal/App/inc/telemetry.h`），波特率 `TELEMETRY_BAUD` |

- 视觉和底盘两路均为 **921600 baud，8 数据位，无校验，1 停止位，无流控**；遥测波特率按蓝牙模块设置。
- 使用匹配的 3.3 V TTL 电平并共地，发送端 TX 接云台 RX；不能直接接 RS-232 电平。
- ASCII 编码，英文逗号分隔、小数点为 `.`，帧内不含空格。
- 每帧以 LF（`\n`）结束，也接受 CR 或 CRLF。发送缓冲中的 NUL 结尾不发送。
- 一帧不含 CR/LF 最长 **191 字节**。超长、非 ASCII 或串口错误后丢弃到下一个换行再恢复。
- 同一帧可跨多次串口接收，一次接收也可包含多帧。未完成帧的接收间隔超过 100 ms 时丢弃该帧。
- 云台中断仅拼帧、入队；任务中进行校验、解析、模式切换。每路队列最多保留 7 个待处理帧；队满丢弃新帧并计数。
- 视觉、底盘到云台是**发送端周期广播、云台接收**，没有串口 ACK。`HAL_UART_Transmit` 成功不代表云台已进入某模式。云台到底盘只回一种帧：`$G` 就绪状态（第 4.1 节），供底盘上电自动跑圈用。

## 2. 新协议公共格式

```text
$正文*CRC16\n
```

CRC 为 CRC-16/CCITT-FALSE：多项式 `0x1021`，初值 `0xFFFF`，不反射，最终异或 `0x0000`。计算范围是 `$` 之后、`*` 之前的原始 ASCII 字节，不包含 `$`、`*`、校验字符或换行。输出 4 位十六进制 ASCII，大、小写均可。

标准校验向量：`123456789` → `29B1`。例如 `2.5` 与 `2.500` 的值相同，但原始字节不同，CRC 必须分别计算。

每个发送端独立维护 16 位序号 `seq`，每个新观测/新状态帧递增，65535 后回到 0。不需要两块板时钟同步。

- 重复序号不刷新在线时间；在线期间拒绝倒序帧。
- 正向序号差须小于 32768，允许跳帧。
- 超过 300 ms 没有接受的新帧后，允许不同序号重新建立序列，支持发送端重启；与上一帧完全相同的序号仍拒绝。
- 发送端重启归零可能需要等待超时后恢复。持续使用旧序号不能作为心跳。
- 当前没有发送端采集时间戳，在线判断基于云台收到完整帧的时刻。视觉端应丢弃积压图像，避免把旧结果包装成新序号。

## 3. 视觉端 → USART10

```text
$V,1,seq,valid,yaw_error_deg,pitch_error_deg*CRC16\n
$V,2,seq,valid,yaw_error_deg,pitch_error_deg,range_mm,age_ms*CRC16\n
```

版本 2（2026-10-24 起 K230 发送）在末尾增加两个整数：`range_mm` 为相机到靶心的距离（0～20000，无目标时 0），`age_ms` 为 K230 从取到这一帧到发出的耗时（0～1000）。云台对版本 1、2 都接受；版本 2 的字段供车速前馈（`tune_veh_ff`）和按帧延迟补偿（`tune_vision_use_age`）使用，两者默认关闭。

| 字段 | 含义 | 范围 |
|---|---|---|
| `V` | 视觉消息类型 | 固定 |
| `1` | 协议版本 | 固定 |
| `seq` | 观测序号 | 0～65535，十进制整数 |
| `valid` | 是否找到有效方框目标 | 0 或 1 |
| `yaw_error_deg` | 水平角度误差，单位 ° | -180～180，有限数 |
| `pitch_error_deg` | 垂直角度误差，单位 ° | -180～180，有限数 |

视觉端负责识别方框、确定目标中心、计算与瞄准中心的偏差，并转换成**角度误差**。控制板不重复做像素到角度转换。

推荐沿用原视觉算法的角度标定与方向。若新写视觉端，可约定目标在图像右侧时 yaw 误差为正、在下方时 pitch 误差为正，再实测确认电机确实向目标移动。固件保留原来的 `VISION_YAW_DIR=-1`、`VISION_PITCH_DIR=+1`，不要在视觉端重复反向补偿。

有效示例（CRC 已计算）：

```text
$V,1,1,1,2.500,-1.000*3C12
$V,1,2,0,0.000,0.000*A424
```

第二帧表示没有目标。新协议不用 `404`，丢失目标时发送 `valid=0`，两个误差建议为 0，仍须是合法有限值。

发送建议：每次新视觉处理结果发送一帧，建议 30～120 Hz，不超过 250 Hz；丢失目标也继续发送无目标帧。相机/算法停止产生新结果时，不要重复发送过期的有效误差。

控制板行为：

1. 保留 USART10 上电前 5 秒忽略视觉数据的原行为，但底盘消息可提前生效。
2. 新有效帧经死区、方向和动态增益处理，更新目标角度；底层控制仍为 500 Hz。
3. 无目标帧或超过 300 ms 无新有效协议帧时，退出视觉跟踪。正常巡线下沿用原无目标补偿分支，Pitch 不保证保持最后视觉目标。
4. 转弯/底盘掉线保持期间仍接收视觉并维护在线状态，但视觉不能修改控制目标。
5. 退出保持后，必须收到接收时间晚于退出时刻的有效目标帧才恢复视觉。等待期间延续保持补偿，不立即跳回启动 Pitch 基准。

可直接使用 [Python 编码示例](examples/vision_protocol.py)。函数返回待发送的 `bytes`，交给现有串口写接口即可。

## 4. 底盘端 → USART1

```text
$C,1,seq,mode,imu_valid,yaw_deg,pitch_deg,roll_deg,gx_deg_s,gy_deg_s,gz_deg_s*CRC16\n
$C,2,seq,mode,imu_valid,yaw_deg,pitch_deg,roll_deg,gx_deg_s,gy_deg_s,gz_deg_s,speed_mm_s*CRC16\n
$C,3,seq,mode,imu_valid,yaw_deg,pitch_deg,roll_deg,gx_deg_s,gy_deg_s,gz_deg_s,speed_mm_s,task,progress*CRC16\n
```

版本 2（2026-10-24 起底盘发送）末尾增加 `speed_mm_s`：底盘编码器测得的前进速度（30 ms 低通，±3000 mm/s），与 `imu_valid` 无关地发送。云台对版本 1、2、3 都接受。

版本 3（2026-10-30 起底盘发送）再增加画圆任务的两个整数：`task` 为 0（激光打靶心）或 1（画圆；上电默认 `chassis_config.h` 的 `CHASSIS_CIRCLE`，出发前按底盘按键 PB5 切换，或蓝牙 `SET circle 0/1`）；`progress` 为本次跑圈进度，单位千分之一圈（0～9999，`mission_run_progress`：已走距离 ÷（4 × 拐角触发间距），知道终点距离后按终点算，DONE 时正好等于圈数）。云台把它们转发给 K230（第 4.2 节）；收到版本 1、2 时保持上次的值。

| 字段 | 含义 | 范围 |
|---|---|---|
| `C,1` | 底盘消息、版本 | 固定 |
| `seq` | 状态帧序号 | 0～65535 |
| `mode` | 0=允许视觉更新，1=请求姿态保持（转弯准备、转弯及故障保持） | 0 或 1 |
| `imu_valid` | 本帧底盘 IMU 数据是否有效。STM32 自主底盘目前只测 `gz_deg_s`，`imu_valid=1` 表示 gz 有效，其余五个数填 0 | 0 或 1 |
| `yaw_deg` | 底盘航向角，° | -360～360，建议归一化到 ±180 |
| `pitch_deg` / `roll_deg` | 底盘俯仰/横滚角，° | -180～180 |
| `gx_deg_s` / `gy_deg_s` / `gz_deg_s` | 底盘三轴角速度，°/s | -2000～2000 |

坐标约定为底盘 X 向前、Y 向左、Z 向上，角速度按右手定则。姿态采用对应的 yaw/pitch/roll，Yaw 零点可以是上电初始方向，不要求绝对北向。发送端应先进行传感器安装方向转换；原始 rad/s 需乘 `180/π` 后发送。

IMU 未就绪时使用 `imu_valid=0`，六个数填写 0；**模式仍然有效**，不能因底盘 IMU 暂时失效而停止发送转弯状态。

有效示例：

```text
$C,1,10,1,1,90.000,0.000,0.000,0.000,0.000,45.000*1592
```

含义：正在转弯，底盘 IMU 有效，Yaw 为 90°，Z 轴角速度为 45°/s。

发送与切换要求：

- 建议周期 **20 ms（50 Hz）**，每帧都携带当前模式，不能只发一次开始/结束事件。
- 决定转弯后立即发送 `mode=1`，转弯期间持续发送；建议实际转动前留出至少两个发送周期供通信和任务处理。当前没有 ACK，这不是模式已确认的保证。
- 转弯真正结束、准备恢复巡线时发送 `mode=0`，之后继续周期发送。
- STM32 自主底盘在 `PRE_TURN/TURN/REACQUIRE/FAULT` 发 1，其余状态发 0。FAULT 复用现有保持行为，帧格式和接收控制逻辑不变；mode 不是完整故障码。2026-10-22 起底盘填入自身陀螺仪的 `gz_deg_s`（IMU 正常时 `imu_valid=1`），yaw/pitch/roll/gx/gy 仍未测量、填 0；此前固定 `imu_valid=0`、六个数为 0。
- 所有发送必须使用同一份底盘模式状态，避免不同任务分别发互相矛盾的模式。
- 当前固件接收并保存底盘 IMU，通过 `Gimbal_GetChassisState()` 提供给本地程序/调试器。增稳仍使用本板 BMI088；只有打开 `tune_yaw_two_loop` 时，`gz_deg_s` 才作为底盘转速前馈进入 yaw 控制（乘 `tune_yaw_chassis_ff`，方向需先在实物上核对，见 `gimbal_task.c`）。

可直接移植 [C 编码示例](examples/chassis_protocol.c) 和 [头文件](examples/chassis_protocol.h)。典型调用：

```c
/* 每 20 ms 调用一次；UART 发送接口使用底盘工程自己的实现。 */
static uint16_t seq;
static char tx[192];
int count = chassis_encode(tx, sizeof(tx), seq++, turning ? 1U : 0U,
                           imu_ready ? 1U : 0U, yaw_deg, pitch_deg, roll_deg,
                           gx_deg_s, gy_deg_s, gz_deg_s, speed_m_s,
                           circle ? 1U : 0U, progress_permille);
if (count > 0) {
    /* uart_write(tx, (size_t)count); 不发送结尾 NUL。 */
}
```

如使用 DMA/中断发送，应保证 `tx` 在发送完成前不被下一帧覆盖；可用双缓冲或发送完成标志。

### 4.1 云台 → 底盘：`$G` 就绪状态（USART1 TX PA9 → 底盘 USART2 RX PA3）

```text
$G,1,<seq>,<flags>*CRC16
```

- 921600，每 100 ms 一帧（`gimbal_task.c` 的 `gimbal_ready_report`），CRC16 和第 2 节相同。
- `flags`（`gimbal_protocol.h` 的 `GIMBAL_STATUS_*`）：bit1 `CONTROL` = IMU 预热、零偏完成且两个电机都有反馈；bit2 `VISION` = 视觉帧有效、yaw/pitch 误差都 < 1° 已连续 2 s（误差变大或断帧超过 300 ms 就重新计时）；bit0 `READY` = 两者都有。
- 底盘（`bsp_gimbal_link.c`）收到后解析；最近 500 ms 内的一帧 READY 才算就绪（`CHASSIS_GIMBAL_STATUS_TIMEOUT_MS`）。底盘 `STATUS` 第一行的 `gimbal_rx` / `gimbal_flags` / `gimbal_ready` 可以看收到了多少帧、最后的标志。
- 用途：上电自动跑圈（`chassis_config.h` 的 `CHASSIS_AUTOSTART_LAPS`）。云台就绪且底盘自己能 RUN（IMU 校准好、线在探头下、链路正常）、车静止，连续 1 s 后跑 `CHASSIS_AUTOSTART_LAPS` 圈（现为 1 圈；默认打靶心，出发前按底盘按键 PB5 切换成画圆，第 4.2 节），每次上电一次；在那之前底盘调试口收到任何一条认得的命令就取消，按键不会取消。

### 4.2 云台 → K230：`$K` 画圆任务（UART10 TX PE3 → K230 RX）

```text
$K,1,<seq>,<task>,<progress>*CRC16
```

- 每 50 ms 一帧（`gimbal_task.c` 的 `gimbal_task_report`），`task`、`progress` 原样来自底盘 `$C` 版本 3，上电后收到之前为 0、0。
- K230（`vision/protocol.py` 的 `TaskReceiver`）每取一帧图像读一次串口（`timeout` 为 0，不阻塞），只用最新的一帧。`task` 为 1 时瞄准点 = 靶心 + 60 mm ×（−sin θ, −cos θ），θ = 2π × progress / 1000（`geometry.circle_point`；靶面坐标 x 向右、y 向下，从正上方起步，面对靶看逆时针；`config.py` 的 `CIRCLE_RADIUS_MM` / `CIRCLE_DIRECTION`）；为 0 时瞄准靶心。之后照常算到这个点的 yaw/pitch 误差，云台的跟踪控制不变。
- K230 每秒日志末尾 `task=<task>/<进度圈数> rx=<收到帧数>/<坏帧数>`，用来确认收到了没有。

## 5. 模式和掉线规则

| 条件 | 视觉 | 本地增稳 |
|---|---|---|
| 从未收到底盘消息，默认配置 | 可以使用 | 持续运行 |
| 底盘在线，`mode=0` | 可使用有效新帧 | 持续运行 |
| 底盘在线，`mode=1` | 暂停目标更新 | 锁定进入保持时的姿态基准 |
| 已收到过底盘消息，之后超过 300 ms 无新帧 | 暂停目标更新 | 进入/维持保持，不自行退出转弯 |
| 底盘恢复 `mode=0` | 等待退出时刻之后的新有效视觉帧 | 等待时继续保持 |
| 本板 IMU 未就绪/超过 20 ms 未更新，或任一电机反馈超过 100 ms | 停止正常控制输出 | 清 PID，尝试持续发送两轴零速度 |

进入保持时，Yaw 目标取当时的本地 IMU Yaw，仅锁定一次；Pitch 保存当时平台角度和电机角度，使用原无目标分支的补偿关系维持进入时姿态。重复 `mode=1` 心跳不会反复重设目标。保持期间禁用静止目标重设。

默认 `GIMBAL_REQUIRE_CHASSIS=0`，便于原有视觉单板调试。整车联调若要求底盘在线才能跟踪，将它设为 1：上电无底盘消息即进入保持。

上电 IMU 校准未完成时不进入控制；恢复本地传感器/电机反馈后会重新捕获当前控制基准。Yaw 机械限位原点只在首次有效初始化时确定，故障恢复不会重新移动该原点。

## 6. 旧格式兼容与行为变化

仍接受以下不带 CRC 的旧帧：

```text
2.5,-1.0\n
2.5,-1.0,0,0\n
404,404,0,0\n
T,T,T,T\n
N,N,N,N\n
```

- 两个或四个字段的视觉旧帧均可；后两个字段暂不使用，但也必须是合法有限数，绝对值不超过 1000000。其他字段数量拒收。
- 前两个字段任一为 404 表示无目标；有目标时角度范围同新协议。
- 旧视觉帧可从 USART10 或 USART1 注入，USART1 用于调试时不要同时接另一台发送设备。
- 旧 `T/N` 帧可从两路接收；`T`=转弯，`N`=巡线。为了新的掉线判断，**T/N 也必须周期发送，不能只发送一次 N 后永久静默**。
- 新 `$V` 只从 USART10 接受，新 `$C` 只从 USART1 接受，避免串口角色混淆。
- 旧格式没有校验和序号，适合迁移/手动调试；正式整车开发优先使用新格式，不混发新旧协议。

## 7. 限位及联调顺序

Yaw 轴有导电滑环，可连续旋转。`gimbal/App/inc/gimbal_task.h` 的 `GIMBAL_YAW_LIMIT_ENABLE` 控制软件限位：默认 1（Yaw 相对首次有效电机位置 ±60°，参数 `GIMBAL_YAW_LIMIT_MIN_DEG/MAX_DEG`），用于首次联调——若视觉方向符号接反，限位能阻止云台一直转下去；确认云台朝靶转动后改为 0，Yaw 不再限位（多圈电机角度也不会误触发）。调试变量 `dbg_yaw_relative_deg` 显示相对首次位置的累计 Yaw。Pitch 保持原编码器坐标下 ±80°。到限位时禁止继续向外驱动，允许向内回退。

底盘转 90°而云台保持空间方向需要约 90°的相对行程，边跑边打每圈需要 360°，因此整车联调需关闭限位。首次测试仍要确认正速度对应的编码器角度增长方向与限位判断一致。

建议依次验证：

1. 本板 IMU 校准、两轴 CAN 反馈正常，无输入时保持原有运行表现。
2. 视觉端发送小角度误差，检查方向、中心位置和跟踪效果；发送无目标帧。
3. 底盘静止发送 `mode=1`，确认视觉不再改变目标；重复心跳确认不重设基准。
4. 小幅手动转动底盘观察补偿，再逐步验证实际直角弯及机械行程。
5. `mode=0` 后发送新视觉帧，确认恢复跟踪。
6. 断开视觉、断开底盘通信、停止电机反馈，分别检查超时行为。

零速度命令只有在 CAN 仍能发送且电机能收到时才有效；本软件不能保证物理断线的电机停转，电机驱动器的通信看门狗需在整车调试时确认。
