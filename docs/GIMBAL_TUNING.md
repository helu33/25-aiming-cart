# 云台调参与调试手册

本文汇总云台（`gimbal/`）上板调试要用的接线、上电流程、Keil Watch 变量、可在线修改的参数、蓝牙遥测和底盘测试命令。代码以 `gimbal/App/gimbal_task.c`（控制）和 `gimbal/App/gimbal_tune.c`（可调参数的默认值、实测依据和蓝牙调参表）为准，参数改了默认值要同步更新本文。

## 1. 接线

| 设备 | 云台板接口（丝印） | 引脚 | 说明 |
|---|---|---|---|
| K230 视觉 | UART10（4 针） | PE2 RX / PE3 TX | 921600，K230 的 GPIO9 TX 接 PE2，共地 |
| 底盘 | USART1（3 针） | PA10 RX / PA9 TX | 921600，底盘 PA2（USART2 TX，`CHASSIS_GIMBAL_UART 2`）接 PA10，共地 |
| 蓝牙遥测 | UART7（4 针，带 VCC） | PE8 TX / PE7 RX | `TELEMETRY_BAUD`（默认 115200），模块 RX 接 PE8，TX 接 PE7 |
| yaw 电机 | CAN1 | — | JC4010，速度模式 |
| pitch 电机 | CAN2 | — | JC4010，速度模式 |

云台控制板是达妙 DM-MC02（STM32H723，CtrBoard-H7），引脚图见厂家资料。板子丝印的口名和芯片串口编号一致；接线以引脚名为准。

## 2. 上电流程

1. 上电后**不要碰车和云台**，约 14 秒：IMU 先加热到 38～40 ℃（`dbg_imu_warmup_ms`），再在静止窗口里测陀螺仪零偏（被碰会重测，`dbg_imu_bias_restarts` 增加）。
2. `dbg_control_ready` 变成 1 后云台开始控制；视觉数据在上电 5 秒后才会被接受。
3. 上电时的电机角度就是 pitch 限位（±80°）的原点，只记录一次。
4. 上电照常对着靶（相机在云台上，朝向别处就看不到靶）。车速前馈用的车头方向 `tune_yaw_fwd_deg` 是标定好的常数（yaw 电机编码器是绝对式的），与上电时怎么摆车无关。
5. **上电自动跑 1 圈，默认打靶心，出发前按一下底盘按键（PB5）改成画圆（第 3 题，见 5.14）**：车放在起点的线上、靶在视野里，上电后不用发任何命令。云台预热完、视觉稳定锁靶 2 s 后回报就绪（`$G`，见 `docs/GIMBAL_COMM_PROTOCOL.md` 4.1），底盘自己也能 RUN 且车静止 1 s 后自动出发，一般在上电后约 20 s。每次上电只跑一次，再跑就重新上电，或者用蓝牙发 `RUN`。
   - 按键：底盘蓝灯亮后（IMU 校准完）到出发前，每按一下在打靶心 ↔ 画圆之间切换，底盘蜂鸣器响 1 声 = 打靶心、2 声 = 画圆；画圆时激光会马上跳到圆的正上方（进度 0 的点）。按完至少等 2 s 才出发（手离开车）。已经出发、或者蓝牙命令取消了自启动之后，按键不起作用。蓝牙 `STATUS` 第一行末尾 `circle=` 是当前模式，`key=1` 表示按键正按着。
6. 只想调试、不想让车自己跑：在云台就绪前往底盘蓝牙口发任意命令（例如 `STATUS`），自启动就取消了；`telemetry_log.py run` 一连上底盘就会发 `--chassis-pre` 里的命令，也会取消。车不在线上也不会出发。
7. 蓝牙模块可以拆掉，跑圈、按键选模式都不需要它（参数是编译进去的默认值，蓝牙调参本来就只在 RAM 里）。两块板蓝牙口的 RX（云台 PE7、底盘 PD2）都开了内部上拉，模块拔掉后引脚不会悬空收到乱码；否则单个干扰字节 `F` 会被云台当成重新标定车头方向的命令。拆掉后就没有遥测和远程 `STOP` 了，急停只剩电源开关。

## 3. Keil Watch：先看哪些

Keil 设置：View → Periodic Window Update 勾选；运行中双击数值即可修改 `tune_*`。若想跑完车再连 ST-Link 读数而不复位：Options → Debug 取消 Load Application at Startup 和 Run to main()，Settings 里 Connect 选 Normal、取消 Reset after Connect。

| 分组 | 变量 | 正常值 / 含义 |
|---|---|---|
| 总状态 | `dbg_control_ready` | 1 = 正在控制 |
| 视觉 | `dbg_vision_valid`、`dbg_vision_frames` | 对靶时 1；帧数每秒约 +23 |
| | `dbg_vision_yaw_err` / `dbg_vision_pitch_err` | K230 报告的误差（°），静止对准时 yaw < 0.05、pitch < 0.15 |
| | `dbg_vision_*_err_max` / `_min` | 自上次清零以来的极值（有效帧），测一趟前写 0 |
| 跟踪滤波 | `dbg_track_yaw_rate` / `dbg_track_pitch_rate` | 估计的靶方向速度（°/s），静止约 0，不跟踪时为 0 |
| | `dbg_track_resets` | 每次上靶 +1，静止时不该一直涨 |
| | `dbg_vision_lookback_ms` | 约等于 `tune_vision_latency_ms` |
| yaw | `dbg_yaw_error`、`dbg_yaw_speed_rpm` | 目标与 IMU 的方位差（°）、电机指令（rpm，限幅 ±50） |
| pitch | `dbg_pitch_error`、`dbg_pitch_speed_rpm`、`dbg_motor_pitch_deg` | 静止时误差在 0.1° 死区内，指令约 0 |
| 底盘链路 | `dbg_chassis_rx_bytes` / `dbg_chassis_frames` / `dbg_chassis_uart_errors` | 字节与帧数持续增加（帧约 50/s）；字节为 0 查接线 |
| | `dbg_vision_suspended` | 默认一直 0；`turnhold=1` 时底盘转弯为 1 |
| | `dbg_chassis_link_lost` | 底盘链路收到过后又断了（超过 300 ms 没帧）为 1，蜂鸣器响；视觉照常跟踪 |
| | `dbg_chassis_gz_deg_s`、`dbg_yaw_motor_rate_deg_s` | 手转车身时应一正一负（见 5.3） |
| IMU | `dbg_imu_temp_c`、`dbg_imu_warmup_ms`、`dbg_imu_bias_z_deg_s` | 约 38.6 ℃、约 14000、±1 以内 |
| 电机保护 | `dbg_axis_stall_count[0/1]` | 指令 ≥5 rpm 但 0.5 s 不动时 +1 并重新使能；正常应为 0 |
| 遥测 | `dbg_telem_init_ok`、`dbg_telem_frames`、`dbg_telem_skipped` | 1；持续增加；基本不变 |

## 4. 可在线修改的参数（`tune_*`）

定义和每个默认值的实测依据都在 `gimbal/App/gimbal_tune.c`，蓝牙名字见文件末尾的调参表。

| 参数 | 默认 | 作用 | 怎么调 |
|---|---|---|---|
| `tune_vision_latency_ms` | 80 | 拍照到云台收到一帧的延迟，用于把误差加到拍照时的角度上 | 上靶时冲过头 → 加大；跟得慢、欠补 → 减小（上限 200） |
| `tune_track_alpha` | 0.5 | 跟踪滤波器每帧信任测量的比例 | 静止时细小抖动 → 0.3；跟手不够 → 0.6～0.7 |
| `tune_track_beta` | 0.17 | 速度估计更新快慢，常取 α²/(2−α) | 前馈关时 0.22 最好，0.3 实车振荡；前馈开时 0.17 与 0.22 一样，取 0.17 |
| `tune_track_ff` | 1.0 | 速度前馈比例 | 0 = 关闭（用来对比），1 = 全开 |
| `tune_yaw_kp_scale` | 2.0 | 旧 yaw 结构下 Kp 的倍数（旧结构里 Kp 实际只剩 1/8） | 实车 4 静止时小幅来回抽，取 2 |
| `tune_yaw_two_loop` | 1 | 1 = yaw 用两层环（见下）；0 = 旧结构 | 2026-10-24 整圈：转弯落后约为旧结构一半，默认打开；换车或改线后先做 5.3 的方向确认 |
| `tune_yaw_kpos` | 8.0 | 两层环外环：每差 1° 期望多少 °/s | 晃 → 4；慢 → 12～16 |
| `tune_yaw_krate` | 7.0 | 两层环内环：用转台陀螺仪压住转速误差的强度 | 一般不动 |
| `tune_yaw_chassis_ff` | 1.0 | 两层环里底盘 gz 前馈的比例和方向 | 方向反了改 −1；0 = 不用底盘 gz |
| `tune_yaw_pos_rate_max`（`posmax`） | 40 | 两层环位置项 kpos × 误差的上限（°/s），跟踪速度和底盘前馈不受限 | 大误差锁靶时仍甩得厉害 → 30；锁靶太慢 → 60 |
| `tune_track_settle_ms`（`settle`） | 300 | 跟踪器每次（重新）开始后，这段时间只跟位置、不学速度 | 出弯锁靶后来回甩 → 加大；0 = 关闭 |
| `tune_track_rate_clip_deg`（`rateclip`） | 0.4 | 跟踪器学速度时单帧残差的上限（°），单帧视觉跳点推不动速度 | 0 = 关；出现左右来回甩时可试 0.3 |
| `tune_turn_hold`（`turnhold`） | 0 | 0 = 转弯时视觉照常，跟踪器在弯里只修位置、不学速度；1 = 转弯时暂停视觉、按 IMU 保持方向 | 2026-10-24 整圈：暂停时出弯误差 4～6°，不暂停时 ≤ 1.6° |
| `tune_veh_ff`（`vehff`） | +1 | 车速前馈：用底盘车速和 K230 测的靶距离直接算靶方位变化率，作为跟踪滤波的已知输入 | 0 = 关；符号由硬件决定，与靶在哪一侧无关（反了误差会翻倍） |
| `tune_veh_pitch_h`（`pitchh`） | −0.182 | pitch 车速前馈：靶心比相机高多少（m，靶心高于相机取负），仰角变化率 = h·v·cosφ/r² | 练习场地量得 0.182 m，实车验证（pitch rms 0.44 → 0.35°）；换场地重新量 h；0 = 关 |
| `tune_yaw_fwd_deg`（`yawfwd`） | 31.8 | 激光沿车身中线朝前时的 yaw 电机角（绝对编码器，常数） | 云台或电机重装后：靶放在车正前方约 1 m、锁定后蓝牙发 `F`，再改代码里的 `VEH_CHASSIS_FORWARD_DEG` |
| `tune_vision_use_age`（`useage`） | 0 | 1 = 延迟用 K230 报告的本帧耗时 + `latencyx` 代替固定的 `latency` | 车速前馈打开后再试 |
| `tune_vision_extra_ms`（`latencyx`） | 40 | 取帧之前的时间（曝光、读出） | 上靶过冲 → 加大 |
| `tune_yaw_rate_ki`（`ratei`） | 40 | 两层环内环的积分（1/s）：累加 (w* − 转台陀螺仪)，补电机跟不上的部分；方位误差 ≥ 3° 时不积、输出打满时不往打满方向积 | 2026-10-28 三圈（0 / 20 / 40 / 60）：弯里 yaw rms 0.52 / 0.44 / **0.29** / 0.31°，直道 p99 1.47 / 1.09 / **1.06** / 1.36°，60 时直道转台多晃约 20%，取 40。驱动器速度环调快（5.10）后重新比较 20 / 40；静止或直道左右来回晃 → 降一档；0 = 关 |
| `tune_yaw_rate_i_max`（`rateimax`） | 60 | 积分的上限（°/s） | 一般不动 |
| `tune_yaw_gz_lead_s`（`gzlead`） | 0.1 | 转弯时底盘 gz 前馈超前的时间（s）：gz + gzlead × dgz/dt，只在 `$C` 报转弯时用，上限 ±80 °/s | 2026-10-29 三圈：0 → 0.1，弯起步 0.6 s 内 yaw 峰值平均 0.51 → 0.40°、最大 0.78 → 0.71°；0 = 关 |
| `tune_yaw_gz_tail_ms`（`gztail`） | 150 | 转弯标志熄灭后 gz 超前（gzlead）再保持的时间（ms）。弯尾 gz 约 0.1 s 内 22 → 8 °/s，标志正好在这时熄灭，超前没加上，电机滞后，转台多转 | 2026-10-29 所有跑次、所有弯：弯尾后 0～0.1 s 转台世界角速度比指令多 1.4～2.0 °/s，第 4 弯出口平均 −0.47° 的约一半。3 圈 0 / 150 / 300：直道 yaw rms 0.16 / 0.13～0.14 / 0.14，第 4 弯出口 yaw rms 0.28～0.30 / 0.24～0.27 / 0.35，全程最大 0.75～1.07 / 0.83～0.84 / 1.21（300 时出弯循迹的小修正也被超前放大），所以定 150；0 = 关 |
| `g_pitch_kp`（`pkp`） | 7 | pitch 位置环比例（rpm/°）。pitch 误差主要是电机落后于目标角（视觉 pitch 误差与 pitch 环误差相关 0.62～0.65、斜率约 1） | 2.8 / 4 / 5.5 / 7：直道 pitch rms 0.36 / 0.30 / 0.27 / 0.22°，没有振荡；电量低时静止抖动 0.004 → 0.022°，余量变小，所以停在 7；静止抖动或嗡嗡响就降一档 |
| `tune_veh_speed_lead_s`（`vlead`） | 0.05 | 车速前馈（yaw v·sinφ/r、pitch h·v·cosφ/r²）用的车速超前时间（s）：v + vlead × dv/dt，dv/dt 由相邻 `$C` 车速差分并低通，超前量上限 ±0.2 m/s。`$C` 车速比真车速晚 70～90 ms，加速段离靶近时方位转速会少估 | 2026-10-29 三圈：0 / 0.08 / 0.05，加速段 yaw rms 0.26～0.50 / 0.09 / 0.13°，起点边最大 0.61～1.03 / 0.45 / 0.29°，全程最大 0.82～1.04 / 0.90 / 0.75°；0.08 出第 4 弯（离靶最近）rms 0.34°，0.05 为 0.28°，所以定 0.05；0 = 关。出第 4 弯剩下的 ~0.5° 不是车速延迟（试过让底盘发指令车速，更差），里程计重建的几何显示前馈只差 2～5%；尖峰跟着弯尾底盘转动急停走，与起步加速度无关（accel 0.5 无改善，见 `gztail`） |
| `tune_telem_select`（`tsel`） | 0 | 遥测通道 9/10 的内容：0 = yaw 电机实测 rpm / 底盘 gz；1 = 云台 IMU pitch / pitch 跟踪速度；2 = pitch 车速前馈 / 车速 (cm/s)；3 = gz 超前量 / dgz/dt；4 = yaw 车速前馈转速 / 前馈实际用的车速 (cm/s，含 vlead) | 诊断用，不占额外带宽；参数存在 `<名字>_params.txt` 里，`report` / `vision` 看到 tsel≠0 时改用转弯标志对齐时钟（不再拿通道 10 当底盘 gz） |

pitch 的视觉增益由跟踪滤波器决定（α、β）；pitch 静止死区 `g_pitch_hold_deadzone_deg` 为 0.1°。

两层环：外环 `w* = tune_track_ff × 跟踪速度 + tune_yaw_kpos × 方位误差`（°/s），内环 `rpm = (w* − tune_yaw_chassis_ff × 底盘 gz + tune_yaw_krate × (w* − 转台陀螺仪) + 积分) / 6`。仿真（`gimbal/tools/track_sim.py`）里 90° 弯的激光甩动：旧结构 2.71°，两层环 kpos 8 加底盘 gz 前馈 0.34°——但那里假设电机 20 ms 跟上指令。实测（2026-10-28，遥测通道 9）yaw 电机带着转台像一个**约 150 ms 的一阶滞后**（增益约 0.85），按实测电机的仿真（`gimbal/tools/rate_integral_sim.py`）弯里峰值 1.47°，与实车 1.2～1.8° 一致；电机快到 60 ms 时为 0.64°。内环积分 `ratei` 40 在实车上把弯里 yaw rms 从 0.52° 降到 0.29°（仿真低估了它：实际电机不只是滞后），剩下的仍可以靠驱动器速度环（5.10）再降。

## 5. 调参流程

按阶段往下走：每个阶段只改一两个参数，达到验收再进入下一阶段。命令里 `COM13` 是云台蓝牙口、`COM10` 是底盘蓝牙口（这台电脑上 HC-05 = COM13，Makerobo = COM10），换了电脑按设备管理器里的口号改；`run` / `set` / `get` 的用法见第 6 节。

### 目标
激光偏离靶心 ≤ 2 cm；靶在 80 cm 处约 1.4°。

| 场景 | 指标 | result7（10-22） | 验收 | 理想 |
|---|---|---|---|---|
| 静止 | yaw / pitch 视觉误差 | 约 0.05° / 0.1° | ≤ 0.15° | ≤ 0.1° |
| 静止 | 上靶过冲 | 约 13% | ≤ 20% | ≤ 10% |
| 直线 DRIVE | 有效帧比例 | 80% | ≥ 90% | ≥ 95% |
| 直线 DRIVE | yaw 误差均方根（rms） | 1.41° | ≤ 1.0° | ≤ 0.7° |
| 直线 DRIVE | yaw 最大误差（起步、停车） | 3.7° | ≤ 2.5° | ≤ 1.4° |
| 转弯 | 出弯后回到 0.5° 以内的时间 | 未测 | ≤ 0.5 s | ≤ 0.3 s |
| 转弯 | 转弯时激光甩开的最大角度 | 未测 | ≤ 3° | ≤ 1° |

仿真（`gimbal/tools/track_sim.py`，DRIVE 20 60、靶约 0.5 m）：只调参时 yaw 最大误差约 2.5～2.9°，加车速前馈约 0.4～0.7°。

**规则**：`S` / `--set` 改的参数保留到云台重启，`run` 只重设 `--set` 里写的那几个。每组都把前面选定的值写全，并写明 `vehff=0` 或 `vehff=1`，否则上一组打开的前馈会带到下一组。

### 5.0 准备
1. 三块板用同一版程序：底盘、云台各烧一次；K230 用 `powershell -ExecutionPolicy Bypass -File vision/deploy.ps1 -Target E:\`（E: 换成 SD 卡盘符）。烧录顺序无所谓。
2. 检查车速前馈要用的两个量（ST-Link 连着、车不动）：对靶时 `dbg_vision_range_m` ≈ 相机到靶的距离（m）；车轮架空发 `DRIVE 20 60`，`dbg_chassis_speed_m_s` 约 ±0.2（是负值就记下来，5.4 用 `vehff=-1`）。
3. 每次上电照常对着靶，14 秒内不碰车（第 2 节）。
4. 镜头干净、靶纸平整、电池充足；车的起点和靶的位置每次一样（地上贴胶带）。
5. 能打印 `#P ...` 就可以开始：

```bash
py -3.13 gimbal/tools/telemetry_log.py get COM13
```

### 5.1 静止精度和延迟（`latency`）
1. 对靶录 5 秒，不发 DRIVE；yaw rms ≤ 0.1°、pitch rms ≤ 0.15° 为达标：

```bash
py -3.13 gimbal/tools/telemetry_log.py capture COM13 --seconds 5 -o s1.csv --plot s1.png
```

2. 上靶过冲（重现刚锁上靶的情况）：录 15 秒。用纸片挡住镜头（不碰云台），挡着时把靶纸横向平移约 5 cm（靶不能动就把车横向平移 5 cm，不要转车），挡够 1 秒再拿开，云台重新锁靶并摆过去；左右来回 2～3 次。`vision yaw error` 每次拿开时跳到约 5°（5 cm / 0.5 m），再回到 0；冲到 0 另一侧的峰值 ÷ 跳变量 = 过冲比例。超过 20% → `latency=100`；回得慢、一直不过零 → `latency=60`；在 60～120 之间选过冲最小的。一般 80 合适。
3. 挡镜头期间激光应停在原处不动。

### 5.2 跟踪滤波（`beta`）

### 5.10 yaw 驱动器速度环（Motor tool）
报表的 `yaw motor lag tau (fit)` 是 yaw 电机跟指令的时间常数。出厂速度环（速度 Kp 0.05 / Ki 0.5）带着转台实测 130～200 ms，是弯里落后约 1°、直道转台跟着车头晃的主要原因（见第 4 节）。说明书 3.4：负载大时调大 PI，且必须在电机静止时改。
1. 车断电，只给云台供电；CH340 接 yaw 驱动器，Motor tool「读取参数」（看到「读取成功」才是驱动器里的值）。
2. 一次只改一项：速度 Kp 0.05 → 0.08 →「保存并重启」→ 整车重新上电；静止对靶 5 秒，转台不嗡嗡响、不来回抖，再跑 3 圈看 `tau` 和弯里误差。
3. 依次 Kp 0.1、Ki 0.8、Ki 1.0；出现嗡嗡声、静止抖动或电机发热就退回上一档。
4. 目标：`tau` ≤ 80 ms（仿真：100 ms 时弯里峰值约 1.0°，60 ms 时约 0.64°）。速度环快了以后，`krate`（7）可能偏大，静止抖就降到 5。

**实测结果（2026-10-28，ratei 40，各三圈）**：速度 Kp 0.05 / 0.08 / 0.1 时 `tau` 160 / 130 / 130 ms，弯刚开始电机实测 / 指令都是 0.69～0.70，弯里 yaw rms 0.29 / 0.32 / 0.32°、峰值平均 0.85 / 0.81 / 0.82°——跑圈没有变化；只有静止更稳（yaw 抖动 0.11 → 0.024 → 0.012°）。电机跟不上不是驱动器速度环 P 太小（多半是转台惯量 / 阻力要的力矩在弯一开始跟不上），所以没再试 Ki，弯里靠 `ratei`（第 4 节）。yaw 驱动器现在是**速度 Kp 0.1 / Ki 0.5**（存在驱动器里）；换驱动器或擦除参数后照此设回。

### 5.11 pitch 车速前馈复核（`pitchh`）
直道 pitch 误差约 85% 是慢变的系统偏差：第 1 弯后那条边（离靶越来越远）平均约 +0.18°、第 3 弯后（朝靶开）约 −0.22°。

**实测结果（2026-10-28）**：`pitchh` −0.182 / −0.15 / −0.12 各三圈，各边、各段的 pitch 偏差不变（6 次三圈都一样：出第 1 弯后 0.75 s 内 +0.51～+0.60°，第 3 弯后那条边的中后段 −0.38～−0.45°），所以不是 h 的问题，`pitchh` 保持实测的 −0.182。这两处正是仰角变化率突变的地方（刚背离靶开出去；越来越近时按 1/r² 变快），是跟踪器学新速率的动态滞后；车停着时视觉误差为 0（闭环会把静态视觉误差压到 0，所以静态测试看不出标定偏差，只能看出这里是动态的）。都在 1.4° 的预算内，暂不处理；要追就先把 pitch 跟踪速率和 pitch 前馈量加进遥测。

### 5.12 K230 掉帧
K230 和云台都更新到 2026-10-28 之后的程序，跑圈后用第 6 节的 `vision` 看每段的原因；拆 SD 卡方便时也可以用 `deploy.ps1 -FrameLog` 记每帧更细的数据（阈值、倾角、重投影误差、距离），再用 `vision/tools/framelog_report.py` 对齐分析。
掉帧集中在正方形离靶最远的一侧（2026-10-28 四次三圈）：第 2 弯有效帧 59～75%，第 1 弯后那条边的后段约 68%，远边后段约 62%，第 3 弯后开头约 75%；第 1、4 弯接近 100%。那里转台转速不高，不是运动模糊，更像靶在画面里变小后检测不稳。要分清是「没检测到」还是被重投影门限（画面对角线 5%）拒掉，需要跑圈时同时录 K230 日志。贴着靶开过的那一小段（方位变化 50～59°/s）有效帧约 84%。


输出有效帧比例、误差极值和均方根、电机打满比例，以及每个弯后的误差峰值和回靶时间。

**不接 ST-Link 调参**：`set` / `get` 通过云台蓝牙改参数和查看参数；`run` 一条命令完成一组测试：改参数 → 开始录制 → 1 秒后通过底盘蓝牙发 `DRIVE` → 录完分析、出图，同时把当时的参数存到 `<文件名>_params.txt`。

```bash
py -3.13 gimbal/tools/telemetry_log.py set COM13 beta=0.3 kpscale=2
```

```bash
py -3.13 gimbal/tools/telemetry_log.py run COM13 --chassis COM10 --set beta=0.3 -o result8
```

`COM13` 是云台蓝牙口（HC-05），`COM10` 是底盘蓝牙口（Makerobo）。不给 `--chassis` 时，工具提示后由你手动发 `DRIVE`。端口号要写在 `--set` 前面。

蓝牙口第一次打开常会超时（`OSError ... 121`，信号灯超时）：工具自动重试 3 次，等数据开始流动后再发命令，命令没回复会重发。`run` 开始前打印底盘的 `HW ...` 状态行（含固件编译时间 `fw=` 和当前 `turn_mm_s`，用来确认烧进去的是新程序），结束时打印底盘对 DRIVE 的回复（`AUTO DRIVE START` / `DONE` / `REJECTED reason=...`）。

`run` 的底盘选项：`--chassis-pre` 在 RUN 之前依次发命令，每条都等底盘确认（`LAPS n` 用 `STATUS` 里的 `laps=` 核对，`SET` / `TURN` 看 `AUTO SET` / `AUTO TURN` 回复，`LOG ON` 看 `AUTO LOG ON`），没确认就重发，被拒绝（`REJECTED`）就不跑；`--chassis-log` 把底盘发来的全部内容（`LOG ON` 的 `D,` 行，50 Hz）存成文件。实时遥测收到的帧明显不够时，跑完马上拉一次板上记录（最近 60 s），帧数比实时多才替换。

底盘命令（底盘蓝牙口，停车时）：`LAPS 1..5`、`RUN`、`STOP`、`DRIVE <cm/s> <cm>`、`STATUS`、`TRACE`、`LOG ON/OFF`、`TURN <cm/s>`（过弯速度）、`SET <名字> <值>`、`PARAMS`（见 5.9）。

**对比报表**：几次跑圈并排比较（读 `<名字>.csv` 和 `<名字>_chassis.txt`）：

```bash
py -3.13 gimbal/tools/telemetry_log.py report s5_motor s8_smooth s9_kg1
```

**掉帧原因**（按赛道位置：每个弯、每条边按出弯后 0–1 / 1–2 / 2+ s 分段，给出视觉有效的时间比例、主要原因和有效 / 无效时靶的面积）：

```bash
py -3.13 gimbal/tools/telemetry_log.py vision kp10b
```

报表内容：直道 / 弯里的 yaw、pitch 均方根和 p99、最大值（只算视觉有效帧，并去掉每次重新锁靶后 1 s，视觉丢失单独计数）；每个弯的视觉有效帧比例；每条边的 pitch 平均偏差；yaw 电机滞后拟合（时间常数、增益）；底盘直道车头角速度、甩头次数、循迹误差和出弯误差。弯的起止取自底盘日志，用云台收到的底盘 gz 对齐两边的时钟（没有底盘日志时用遥测里的转弯标志）。定义写在 `gimbal/tools/run_report.py` 开头。

## 7. 常见问题

| 现象 | 先查 |
|---|---|
| pitch 发烫、轻推就滑一大截 | 驱动器极对数（JC4010 出厂 14）；用厂家上位机读两台参数对比 |
| 上电后 yaw 慢慢漂 | 上电 14 秒内被碰过（看 `dbg_imu_bias_restarts`）；IMU 温度 |
| pitch 上下跳 | K230 大量 `valid=0`（`pose reprojection error`）：擦镜头 |
| 激光停在靶心旁固定偏几毫米 | 激光标定；K230 光斑闭环 `SPOT` 是否开启 |
| 底盘 gz 一直 0 | `dbg_chassis_rx_bytes`：0 = 接线/共地；有字节没帧 = 波特率或干扰 |
| 蜂鸣器响 | 底盘链路收到过后又断了（`dbg_chassis_link_lost`）：查底盘→云台数据线和供电；视觉照常跟踪，只是没有底盘前馈 |
| 电机突然没劲 | 驱动器温度保护触发；`dbg_axis_stall_count` 应自动重新使能 |
| `could not open port ... 121`（信号灯超时） | 电脑连不上蓝牙模块：模块是否上电；是否被 VOFA+、串口助手或手机占着（同时只能连一个）；关掉后等 5 秒再试；仍不行在 Windows 里关开一次蓝牙 |
| `COMx does not exist` | 口号不对：看工具列出的口，或设备管理器里蓝牙「传出」口 |
| `chassis: no answer to DRIVE` | 底盘口号不对或蓝牙没连上；底盘正常时每秒都会发一行 `AUTO ...` / `HW ...` |
| `AUTO DRIVE REJECTED reason=imu_not_ready` | 底盘 IMU 上电校准没过：上电时不要动车，看 `HW` 行的 `calib`、`imu_read` |
| 说跑 3 圈只跑了 1 圈 | `LAPS 3` 在蓝牙上丢了（底盘默认 1 圈）：用 `--chassis-pre "LAPS 3"`，它会确认后再开跑 |
| `SET` / `TURN` 回 `AUTO UNKNOWN COMMAND`、`HW` 行没有 `turn_mm_s` | 底盘还是旧程序：Keil 里 Rebuild 再下载，看 `HW` 行的 `fw=` 时间 |
| 云台参数列表（`G`）末尾被截断 | 云台还是旧程序（回复缓冲区 2026-10-28 从 200 加到 256 字节） |
| 弯里一直落后约 1°、直道转台跟着车头晃 | yaw 驱动器速度环太慢：报表的 `yaw motor lag tau` > 100 ms 就按 5.10 调 |
| Motor tool 显示的参数不对 | 没点「读取参数」时显示的是界面默认值，不是驱动器里的值（2026-10-28 误以为 yaw 极对数是 7） |
